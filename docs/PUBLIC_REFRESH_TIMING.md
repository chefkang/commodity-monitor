# 公开监测刷新时点说明

更新时间：2026-06-19

## 结论

- 2026-06-19 实测表明，今天的公开行情数据在北京时间 09:09 左右已经可以刷新出 `2026-06-19` 交易日。
- 旧逻辑把“上午档成功”近似等同于“生成时间必须晚于 10:00”，这会把 09 点多已经落地的今天数据误判成未刷新。
- 现在的处理改成了两层判断：
  - 如果上午 10:00 前已经刷出当天交易日，只能视为“部分品类可能已提前换日”；页面必须同时展示覆盖比例。
  - 到了 10:00 之后，若本地生成时间仍早于 10:00，后续刷新任务必须再跑一轮，不能只因为少数品类切到当天就跳过。
  - 如果 10:00 前重跑后仍然只有上一交易日，就继续等待下一轮预设重试，不再把它误记成失败。

## 自动化调整

- 本地刷新任务增加了更早的早间重试：`09:05`、`09:20`、`09:40`、`09:58`。
- 公网发布兜底增加了更早的跟进：`09:12`、`09:32`、`09:52`。
- 健康检查增加了更早的晨间巡检：`09:22`、`09:42`、`10:05`。

## 页面解释口径

- 如果还没到 10:00，但最新交易日已经切到当天，页面应显示“今日首轮已提前刷新”，同时必须显示 `N/总数` 的行情日期覆盖情况。
- 如果还没到 10:00，且最新交易日仍是上一交易日，只能算“正常等待”，不应直接判成故障。
- 公开页上的“最新交易日”和“页面生成时间”必须继续分开解释，避免把“行情覆盖日期”误读成“页面没刷新”。
- 页面展示“最新交易日”时，应优先使用 payload 顶层的 `latest_trade_date`，不要再从单项明细里的 `item.date` 自行反推；因为首轮已提前刷新时，系统最新交易日可能已切到今天，但单项明细日期仍停留在上一交易日。
- 页面顶部不能只写“最新交易日 YYYY-MM-DD”。如果 `dominant_trade_date` 仍早于 `latest_trade_date`，必须明确写出“部分更新，主行情仍是上一交易日”。

## 混合交易日说明

- 页面或简报如果显示“今天已刷新，但行情日期混合”，表示脚本和发布已经执行，但不同上游源的换日节奏不一致。
- 这时要同时看 `generated_at` 和交易日覆盖分布，而不是只盯着单个品类的日期。
- 典型提示口径应直接说明覆盖情况，例如“36 个跟踪品类里只有 3 个切到 2026-06-19，仍有 33 个停留在 2026-06-18”。
- 这种状态优先按“上游源尚未全面换日”解释，不应再被健康检查误判成“今天完全正常”或“页面根本没刷新”。

## 生意社直连补充

- `AKShare/生意社现货与期货` 接口有时会晚于生意社公开基准价网页换日。
- 对铜、铝、锡、镍、锌、碳酸锂、PP、PVC、LLDPE、苯乙烯、木浆/纸浆、铁矿石、金属硅/工业硅、天然橡胶、热轧板卷，已配置生意社 `vane` 页面直连补充源。
- 当直连生意社页面已经给出当日基准价时，系统会把它作为公开基准价写入同一品种，派生代理项也随之更新。
- 不要为了追求日期覆盖而硬接不同单位或不同含义的页面：例如玻璃页面的数值口径与当前玻璃期货代理不一致，白银暂未接入稳定生意社基准页。
